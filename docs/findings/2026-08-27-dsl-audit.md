# DSL audit: do five primitives cover the 2022 corpus? — and does the bed boot?

*2026-08-27. Pre-plan desk spikes from RFC 0001 §8: (1) audit every apiTestTask spec against the
proposed v1 DSL before the schema is built; (2) verify the validation bed runs. Cost: $0 in model
tokens — the corpus is read, not executed. Corpus: `apiTestTask/test/specs/**` at `0917488`.*

## Corpus correction

RFC 0001 said "33 hand-written specs." The truth: **32 spec files, 27 executable** — five are
traceability stubs with no test body (`2-3`, `3-2`, `3-3`, `4-7`, `4-8`, each saying "covered by
X"). In Peira those stubs disappear structurally: one intent section may compile to specs
that cover several ACs, and coverage bookkeeping lives in the lineage manifest, not in stub files.
The PR1 gate is restated as: **re-express all 27 executable specs.**

## Verdict: 27/27 expressible, zero escape hatches — with three schema amendments

Every executable spec maps to `request` / `capture` / `expect` / `pollUntil` / `$unique` +
`$users`. No spec needs a code step. The sleeps become `pollUntil`, as predicted. But the audit
surfaced three places where the *vocabulary inside* the primitives was too narrow. None is a new
primitive; all three are schema widenings, and all three are now normative for PR1:

### A. `expect` needs type matchers

12+ specs assert shape, not value: `id: expect.any(String)`, `timestamp: expect.any(String)`,
`message: expect.any(String)` ("some error text exists"). Subset match on literals cannot express
this. Amendment: a closed matcher vocabulary inside expected bodies —

```jsonc
"expect": { "status": 200, "body": { "id": { "$any": "string" }, "result": null } }
```

`{"$any": "string" | "number" | "boolean"}` plus literal `null` (used by `4-5`/`5-3` to assert
result-not-yet-present). Closed list, constants not config; anything richer waits for telemetry.

### B. `auth` needs three forms, not one

The corpus authenticates as: fixture users (`user_1`, `user_2`), deliberately *invalid* literals
(`invalid`/`cred` in 1-3), empty-string credentials (1-4), and valid-user-with-empty-password
(1-6). `$users.*` refs alone cannot express negative auth tests — and negative auth tests are the
security section. Amendment: `auth` is `"$users.<alias>"` | `{ "username": "...", "password":
"..." }` literal | absent (anonymous).

### C. Interpolation must be deep and in-string

The 2022 parsers substituted only top-level, whole-value string properties — a documented
limitation of the ancestor. The corpus needs `$alias`/`$unique` tokens *inside* strings and at any
depth (e.g. a payload of `"int x{{unique}} = 1+1; x{{unique}};"` keeps a known result while
varying the script — the fix for the 2022 "restart the app between runs" problem). Amendment:
`{{token}}` interpolation anywhere a string appears, in requests and expected bodies both.

## Two patterns flagged for the telemetry watchlist (not v1 primitives)

1. **Transient-state assertions.** `4-5` (PENDING) and `5-3` (IN_PROGRESS) assert a state the
   service will *leave*. Expressible in v1: `pollUntil` with the transient state as target and a
   poll interval shorter than the pinned workload (`sleep(1000)` scripts make the window wide).
   Inherently racy in the general case — if compiled specs of this shape recur and flake, that is
   the fallback log asking for an `observe`/`expectWhile` primitive, with evidence.
2. **Paired unique-payload / known-result generation.** `$unique` as a nonce suffices for this
   corpus (comment/variable-name embedding keeps results stable). A future AUT whose response
   *derives from* the unique payload would need generator-paired captures — that is PR4 generator
   territory, not a v1 primitive.

## A drift-adjudication specimen was already in the corpus

Test plan AC 1.4 (intent): fetching another user's request detail → **403 Forbidden**.
Spec `1-5` (encoded reality): asserts **401** with an `Unauthorized` body — the author bent the
spec to observed behavior and the intent/spec divergence is recorded nowhere. This is §4.7's
motivating case, found in the wild, in our own ancestor: an intent compiler would have generated
the 403 expectation, the run would fail, and triage would file the bug instead of the suite
silently endorsing the behavior. Keep this example; it is the pitch.

Minor corpus notes, for completeness: `3-6` and `4-6` are the same test duplicated across folders;
`4-1-7` imports `BAD_REQUEST` unused; the global 100 ms pre-test sleep in the 2022 runner is what
made `1-1`'s COMPLETED assertion pass at all — it becomes an honest `pollUntil` in the port.

## The bed does not boot — and that resolves the right way

`java -version` → no Java runtime on this machine; the groovy jar cannot start locally. Decision
(Timothy, 2026-08-27): **the groovy runner was only ever an application under test, and Peira
targets RESTful APIs generally** — so the validation bed inverts:

- **Primary bed: an in-repo fixture service** — zero-dep Node HTTP server shipped in
  `test/fixtures/`, implementing the same observable semantics the corpus tests (basic auth with
  fixture users, submit/status resources, async jobs, capacity-2 queue, PENDING → IN_PROGRESS →
  COMPLETED/FAILED). The 27 ported specs must run green against it. A fixture we own also lets
  PR5 inject deliberate behavior shifts for triage testing — the Akela-experiment trick.
- **Secondary bed (optional): the groovy jar itself**, for provenance — runs where Java exists
  (the 2022 GitHub Actions workflow ran it on `ubuntu-latest`, which ships a JDK). Nothing in the
  tool may know or care which bed it points at; the config difference is a base URL.

The 2022 test plan remains the PR2 compilation-fidelity corpus either way — intent in markdown
does not need a running service.

## What this changes in RFC 0001

- §4.3: the three amendments (matchers, auth forms, deep interpolation) folded into the primitive
  definitions; corpus count corrected.
- §8: validation bed restated as fixture-first with the jar optional; PR1 gate is "27/27 green
  against the fixture, zero escape hatches, zero sleeps."
- The §8 claim "five primitives, zero escape hatches" **survives the audit** — the risk the spike
  was built to catch (a missing sixth primitive) did not materialize; what it caught instead was
  vocabulary, which is exactly the cheap-to-fix-now kind of finding.
